# SLAM — Product Brief

**Status:** Discovery  
**Product owner:** To be confirmed  
**Platforms:** Android and iOS  
**Implementation:** Dart + Flutter

## Purpose

SLAM is the working name for a mobile application whose exact purpose and audience will be defined from the original requirements. This brief is deliberately a discovery document—not a fabricated product specification.

## What we need to learn

1. Who will use the app, and in what context?
2. What problem or recurring task should it make easier?
3. How is that problem handled today?
4. What is the single most valuable outcome the first version should deliver?
5. What information must the app store, display, or exchange?
6. Does it need accounts, synchronization, notifications, payments, location, camera, or offline support?
7. Are there privacy, accessibility, language, or connectivity constraints?

## Product guardrails

- Keep the first release focused on one core user journey.
- Prefer clear, low-friction mobile interactions.
- Avoid collecting personal data that the app does not need.
- Design for real device sizes and variable network conditions.
- Do not commit to a backend or paid service until requirements justify it.
